# AI Video Pipeline Design - Manga Automation

## 1. Executive Summary

This document outlines the transition of the Manga Automation video generation pipeline from utilizing static, pre-defined Remotion templates to a **fully dynamic, AI-driven "Super Template" system**.

The new architecture will automatically scrape trending manga edits from TikTok, analyze their pacing, style, and effects using Claude (or Gemini), and generate a detailed JSON configuration (a "Super Template") that the Remotion renderer will use to generate highly engaging, trend-compliant videos.

## 2. System Architecture Updates

### 2.1 Trend Detection via TikTok Scraping
To stay relevant, the system must analyze actual TikTok trends rather than relying solely on MangaDex popularity.

*   **Proposed Tool:** **Apify TikTok Scraper**
    *   *Why?* Scraping TikTok directly is notoriously difficult due to advanced bot protection and CAPTCHAs. Apify provides maintained, robust actors (e.g., `clockwork/tiktok-scraper` or `apify/tiktok-scraper`) that can search by hashtags (e.g., `#mangaedit`, `#onepieceedit`) or sounds, and return structured JSON containing video metadata, engagement stats, audio links, and sometimes transcriptions.
*   **Workflow:**
    1.  The `TikTokTrendAgent` (run via cron) triggers an Apify actor to scrape recent videos under specific manga-related hashtags.
    2.  The agent filters for videos with high engagement velocity (views/hour).
    3.  It downloads the top 5-10 trending videos for analysis.

### 2.2 Style Analysis Agent (`StyleAnalyzerAgent`)
Once trending videos are identified, the system needs to deconstruct *why* they are trending.

*   **Workflow:**
    1.  The `StyleAnalyzerAgent` uses **Claude 3.5 Sonnet Vision** (or Gemini 1.5 Pro) to analyze frames of the downloaded trending videos.
    2.  It extracts metadata such as:
        *   Average panel duration (pacing).
        *   Types of transitions used (flashes, zooms, hard cuts).
        *   Motion styles (heavy shakes, slow Ken Burns, 3D panning).
        *   Color grading (high contrast, desaturated, glitch effects).
    3.  It correlates these visual styles with the audio mood (using the scraped audio metadata).

### 2.3 The "Super Template" System
Instead of asking Claude to write raw React Remotion code (which is prone to syntax errors, missing imports, and runtime crashes), the `StyleAnalyzerAgent` will generate a deeply nested, strongly typed JSON configuration. A single "Super Template" React component in Remotion will interpret this JSON and render the video.

**Super Template JSON Schema Example:**
```json
{
  "styleName": "Hype Action Edit (Trend #402)",
  "global": {
    "backgroundColor": "#000000",
    "colorGrading": {
      "contrast": 1.2,
      "saturation": 0.8,
      "vignette": 0.4
    },
    "defaultTransition": {
      "type": "flash",
      "durationFrames": 5
    }
  },
  "pacing": {
    "rhythm": "accelerating", // Starts slow, gets faster
    "minDurationFrames": 15,
    "maxDurationFrames": 90
  },
  "panelBehaviors": [
    {
      "triggerEmotion": "epic",
      "motion": "zoom_shake",
      "easing": "easeOutExpo",
      "overlayEffects": ["particles"]
    },
    {
      "triggerEmotion": "sad",
      "motion": "slow_pan_up",
      "easing": "linear",
      "overlayEffects": ["rain", "desaturate"]
    }
  ],
  "audio": {
    "beatSync": true // If true, panels transition on major audio beats
  }
}
```

**Remotion Implementation (`SuperMangaRecap.tsx`):**
*   The Remotion component receives this JSON via props.
*   It iterates over the selected manga panels.
*   It matches the panel's Claude-assigned `emotion` (from the `PanelSelectorAgent`) to the `panelBehaviors` defined in the Super Template JSON.
*   It dynamically applies the correct CSS transforms, Remotion transitions, and overlay SVG/CSS effects based on the JSON directives.

## 3. Database Schema Changes

To support tracking trends and dynamic templates, we will add new tables and modify existing ones.

### 3.1 `tiktok_trend_reports`
Stores data on viral videos scraped from TikTok.

```sql
CREATE TABLE tiktok_trend_reports (
    id SERIAL PRIMARY KEY,
    manga_id INTEGER REFERENCES manga(id),
    tiktok_video_id VARCHAR(100) UNIQUE NOT NULL,
    original_url TEXT NOT NULL,
    sound_id TEXT,
    views BIGINT,
    likes BIGINT,
    shares BIGINT,
    engagement_velocity DECIMAL(10,2), -- views per hour
    extracted_style_summary TEXT,      -- Human-readable summary of the style
    scraped_at TIMESTAMP DEFAULT NOW()
);
CREATE INDEX idx_trend_manga ON tiktok_trend_reports(manga_id);
```

### 3.2 `dynamic_video_templates`
Stores the JSON configurations generated by the `StyleAnalyzerAgent`.

```sql
CREATE TABLE dynamic_video_templates (
    id SERIAL PRIMARY KEY,
    trend_report_id INTEGER REFERENCES tiktok_trend_reports(id) ON DELETE SET NULL,
    name VARCHAR(200) NOT NULL,
    config JSONB NOT NULL, -- The "Super Template" JSON
    success_score DECIMAL(5,2) DEFAULT 0, -- Feedback loop: how well videos using this template perform
    usage_count INTEGER DEFAULT 0,
    created_at TIMESTAMP DEFAULT NOW()
);
```

### 3.3 Updates to `chapter_posting_queue` and `videos`
*   Add `dynamic_template_id` (FK to `dynamic_video_templates`) to `chapter_posting_queue`.
*   Add `dynamic_template_id` to `videos` to track which AI-generated template was used for analytics.

## 4. Tooling & Pricing Estimates

Operating this pipeline at scale (e.g., 90 videos/day) requires budgeting for scraping, AI inference, database, and compute.

### 4.1 TikTok Scraping (Apify)
*   **Tool:** Apify TikTok Scraper.
*   **Usage:** Scraping ~500 videos/day to find trends.
*   **Cost:** ~$30/month (Apify Personal Plan) + usage costs (~$2-$5 per 1,000 scrapes depending on the actor).
*   **Estimated Monthly Cost:** **$40 - $50**

### 4.2 AI Vision & Text Inference
*   **Tools:** Claude 3.5 Sonnet (Vision for Style Analysis) + Claude 3 Haiku (for fast Panel Selection & Captions).
*   **Usage:**
    *   Style Analysis: ~10 trends analyzed per day (Vision is expensive).
    *   Video Generation: 90 videos/day requiring panel selection and captioning.
*   **Cost Estimate:**
    *   Claude 3.5 Sonnet Vision: ~$0.015 per image. Analyzing 5 frames * 10 trends = 50 images/day = ~$22/month.
    *   Claude 3 Haiku (Text): ~$0.25 per 1M tokens. Very cheap for captions/JSON gen. ~$5/month.
*   **Estimated Monthly Cost:** **$25 - $35**

### 4.3 Compute & Rendering (Remotion)
*   **Tool:** Remotion CLI on AWS EC2 or DigitalOcean Droplet.
*   **Usage:** Rendering 90 videos/day. Remotion relies on headless Chrome; it requires moderate CPU/RAM.
*   **Cost:** Remotion is free for individuals/small creators (check the company size license limit if commercializing heavily).
*   **Infrastructure:** 1x 4-core, 8GB RAM VPS (e.g., DigitalOcean Premium AMD).
*   **Estimated Monthly Cost:** **$24 - $48**

### 4.4 Database (PostgreSQL)
*   **Tool:** Managed PostgreSQL (e.g., Supabase or AWS RDS) to store millions of panels, templates, and queues.
*   **Estimated Monthly Cost:** **$25 - $50**

**Total Estimated Operating Cost:** **$114 - $183 / month**

## 5. Testing Requirements

Transitioning to dynamic AI-generated configurations introduces volatility. Rigorous testing is required.

### 5.1 Unit Testing (Remotion Component)
*   **Focus:** The `SuperMangaRecap.tsx` component.
*   **Approach:** Pass static, heavily malformed JSON configurations to the component and ensure it falls back gracefully to default styles without crashing.
*   **Tool:** Jest + `@remotion/testing`.
*   **Cases:** Missing color codes, negative transition durations, invalid easing strings.

### 5.2 Property-Based Testing (AI JSON Schemas)
*   **Focus:** The output of the `StyleAnalyzerAgent`.
*   **Approach:** Use `fast-check` to generate thousands of randomized JSON configs that pass Zod validation, and ensure the `SuperMangaRecap` component can calculate `durationInFrames` and render a single frame without throwing an error.
*   **Tool:** `fast-check` integrated into existing Jest suite.

### 5.3 Integration Testing (Agent Workflow)
*   **Focus:** The end-to-end flow from Apify -> Claude -> Database -> Queue.
*   **Approach:** Mock the Apify API response and the Claude API response. Verify that:
    1. A `tiktok_trend_report` record is created.
    2. A `dynamic_video_templates` record is created with valid JSON.
    3. The queue is populated with a `chapter_posting_queue` entry referencing the new dynamic template.

### 5.4 E2E Rendering Test
*   **Focus:** Actual video output.
*   **Approach:** Run the `render-video.ts` CLI with a mock dynamic template JSON and verify the output `.mp4` is valid, playable, and meets the 60+ seconds TikTok CRP requirement.
